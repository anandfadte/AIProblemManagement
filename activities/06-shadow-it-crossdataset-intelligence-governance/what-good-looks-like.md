**Expected output structure**
A strong AI output for this activity will contain the following sections / elements:
- Shadow spend quantification table (team breakdown)
- Correlation finding: X% coincidence between shadow-tool access and API errors
- Explicit correlation-vs-causation flag with proposed validation test
- Policy mapping: each finding tied to specific governance clause
- Policy gap identification: specific clause that should have prevented this but did not (§4.1 approval threshold)
- Final executive brief with top-3 remediation actions ranked by cost:impact
**Scoring rubric (5 dimensions)**
**Common failure modes — watch for these**
- Model states 'shadow tools cause API errors'. Response: 'that is causation; the data shows correlation. Reframe.'
- Policy mapping is generic. Response: 'cite the specific §X.Y clause for each finding'.
- Remediation is vague. Response: 'each action needs an owner role, a cost estimate, and a success metric'.
**Debrief question for the room**
Where did the AI add the most value — and where would you NOT trust it without a human review step? Be specific about the failure mode you saw.
Scoring is a facilitation device — not an exam. The point is to make the quality dimensions visible and discussable, so participants internalize what a 'good' AI output looks like for their own work.
